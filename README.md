# 🎡 游乐园主题公园经营模拟（ThemePark Tycoon）

一款可浏览的在线网页版主题公园经营模拟游戏。作为游乐园总经理，你需要规划园区、建设游乐设施与商铺、管理员工、调整票价、举办活动并应对突发事件，把一座空地建成繁华的主题乐园。游戏内置时间模拟引擎，数值实时演算，具备完整的经济循环与成长曲线。

## 技术栈

- **前端**：Vue 3 + Vite + Pinia（状态管理）+ 内联 SVG 图表
- **后端**：Express + Node.js 内置 `node:sqlite`
- **数据库**：SQLite（`server/park.db`）
- **通信**：REST API，Vite 代理 `/api` 到后端
- **启动**：`concurrently` 同时拉起前后端

## 快速开始

```bash
npm install     # 安装依赖
npm run dev     # 同时启动后端(4150) 与 前端 Vite
```

浏览器访问 Vite 输出的地址（默认 `http://localhost:5200`，若被占用会自动切换端口）。

| `partner_contracts` | 联营合同（扣点率/会员优惠商户承担比例/结算周期/保证金/起止日，active→terminated，关联终止清算账单） |

| `partner_settlements` | 联营结算账单（周期账/终止清算：分账−会员优惠承担−FEFO 库存成本−罚没−保证金扣没+保证金退还=应付；draft→paid/overdue） |

## 核心玩法

- **时间模拟**：游戏每 2 秒推进 1 小时，自动结算门票、游乐、商铺收入，扣除运营成本、员工工资与租金，设施健康度随时间衰减。
- **经济循环**：票价影响入园量与单客收入的取舍；声誉由满意度、事件与财务状况驱动。
- **事件系统**：玩家可策划烟火 / 花车巡游等活动，同时会随机遭遇阵雨、设备故障、投诉潮、明星到访等突发事件，需要决策处置以免损伤声誉。
- **设施检修工单**：检修不再即时修复。健康度跌破红线自动停运或运营手动「报修检修」后，设施立即进入停运状态并生成检修工单排队等待；**维修员工接单后按游戏时间推进**（技能/士气/岗位匹配决定速度），每人同时只能检修一台。支持**排队派单、随时转派给空闲维修工、维修工离岗后工单退回排队且进度保留（离岗接续）**。停运期间联动分时预约——关停未来时段并对在途预约**园方全额退款**（同步生成设施故障投诉）；完工时健康度恢复至 100、设施自动恢复运营并**重新开放可售时段**，按健康度核定的检修费用**结算入财务流水**，维修工还可在现场**一并处置关联的设施故障投诉**。升级前已处于检修状态的设施会自动补建排队工单，状态完全兼容。
- **投诉与服务补救**：游客反馈随长队、卫生差、设施故障、排队投诉潮等状况自发产生，也可在「投诉补救」页面前台手动登记。投诉分一般/严重/紧急三级并有处置时限，指派岗位匹配的员工（保安/保洁/维修）推进处置进度；可手动升级或在超时时自动升级，紧急投诉仍超时将引发公开差评事件。现场处置完成后选择道歉/赠票/快速通行券/消费券/现金补偿结案，依据处置质量与补偿档次产生 1–5 星评价，回流声誉、员工满意度与服务口碑，口碑进一步影响后续客流与满意度；不予补偿结案则扣减声誉与口碑，补偿支出记入财务流水。
- **游客预约与分时入园闭环**：在「预约调度」页面，游客可按日期 + 时段预约**入园**或热门**游乐设施**（下单即预收票款，现金制收入确认）。运营人员可逐时段**调整容量、设置超售额度（对冲约 18% 爽约率）、开关时段**；时段库存与设施设备状态联动——设施停运/检修自动关停时段并对在途预约执行**园方全额退款**。每小时引擎自动核销到场预约（也可在闸机/设施口扫码人工核销），核销结果**回写客流（入园人数）、排队（预约游客走快速通道不排队）、设施游玩量、票务（预收/退款流水）与投诉**。一致性处理覆盖四类异常：
  - **改签**：目标时段需有真实容量，库存原子转移（原时段减、新时段增），不加价；
  - **爽约**：过时段未核销自动标记 `noshow`，预收款没收并记「违约」收入；
  - **超售**：到场超出容量时优先自动改签后段时段，无法安置则全额退款并自动生成投诉工单；
  - **退款**：提前取消全额退、当日取消退 50%（其余作手续费）、园方原因/超售全额退，退款同步冲减现金并释放可售名额。
  - 模拟游客会按填充率目标持续为未来三天下单，预约核销占比越高满意度越好（入园/排队更有序）。
- **预约并发一致性与异常恢复**：下单、改签、退款、核销全链路具备生产级一致性防护——
  - **事务回滚**：建单+扣库存+预收款+流水+日志等多步写入包裹在 SQLite 事务（`BEGIN IMMEDIATE`）中，任一步失败整体回滚，不留半完成状态；关闭时段/设施停运的「关时段+批量退款+投诉」同样原子提交；
  - **幂等请求**：前端为每次操作意图生成 `request_id`（UUID），服务端按 `scope+key` 缓存首次执行结果，双击/重试/网络重发直接重放首次结果，不重复建单、不重复扣款、不重复退款；系统级失败（已回滚）不缓存，允许同键安全重试；
  - **库存原子校验**：库存扣减/转移使用条件更新（`UPDATE ... WHERE 余量充足`），命中 0 行即回滚，杜绝超卖与库存蒸发；预约单状态流转（`booked→checked/refunded/noshow`）均为条件更新，重复退款/重复核销返回状态冲突而非二次执行；
  - **批量容错**：每小时自动核销逐单独立事务，一单失败跳过并计数，不拖垮整批；爽约批处理同事务且防重复没收；
  - **超售退款异常补偿（不虚报、可恢复）**：自动/人工核销遇超售且全额退款事务失败（系统异常已整体回滚）时，批处理结果**绝不**把该单计入已安置/已退款（现金未退、库存未释放、预约保持 `booked`），而是持久化到异常补偿队列 `reservation_pending_actions`（记录尝试次数与最近错误）。引擎每小时**先重试补退、再跑爽约扫描**，补退成功才一次性完成退款/释放名额/投诉；持续失败期间该单被爽约扫描显式排除，杜绝"园方欠退款被当成游客爽约没收"的资金倒挂与经营数据虚报；预约若被人工核销/改签/退款先行处置，挂起记录自动作废，重试不会二次退款。新增挂起时登记经营异常事件，统计接口暴露挂起单数；
  - **可追踪错误**：所有失败响应携带业务错误码（`SLOT_FULL`/`RSV_STATUS_CONFLICT`/`TX_FAILED` 等）与服务端请求号（`X-Request-Id` 头 + 响应体 `reqId`），前端展示「中文提示〔错误码 · 请求号〕」，按钮级防重复点击，网络异常也有兜底提示。
- **成长空间**：可扩建未解锁区域、升级设施刺激度、增聘员工提升清洁与服务。
- **游客会员与权益中心**：在「会员权益」页面运营会员全生命周期，与票务、分时预约、商铺消费、退款补偿、财务入账和运营人员配置全链路联动——
  - **购卡与等级流转**：散客前台免费注册即普通会员；可办理**银卡/金卡/钻石卡**（价格、有效期、折扣、积分倍率、开卡赠权益均可在「运营配置」调整）。购卡支持**新购/续费（有效期叠加）/升级（从当前到期日续期）**，有效期内禁止降级；日结自动扫描到期会员卡并**降级为普通会员**（积分与储值保留），等级变化全部写入生命周期日志。会员可被**冻结/解冻**（风控期禁止一切交易）。
  - **积分账户**：按「每 ¥10 实付 = 基准积分 × 卡倍率」在**现场购票、分时预约（入园/设施）、商铺消费**三类场景自动赚分；全额退款按退款比例**回退积分**（当日退 50% 回退一半、爽约不退），积分逐条流水可对账，运营可手动调整。
  - **权益账户与积分商城**：积分可兑换**储值（负债入账，消费才确认收入）、消费券、免票券、快速通行券**；开卡也赠送。**免票券**用于分时入园 0 元预约（1 人），**快速通行券**让会员在时段真实容量售罄时仍可下单、核销时走快速通道直接放行（不参与超售改签），**消费券/储值**在商铺核销（会员享卡折扣，现金/储值/券三种支付）。预约全额退款时**券类权益自动返还、积分按比例回退**；当日取消退 50% 则券不返还。
  - **退款补偿联动**：投诉处置新增「**会员积分补偿**」结案档（0 现金成本，积分额由运营配置），仅会员本人投诉可用；手动登记投诉时可关联会员，补偿积分在会员中心独立事务发放并回流评价。
  - **财务入账**：卡款（会员卡）、储值充值（会员储值，负债）、储值消费（商业·负债转收入）、券核销（会员权益·营销成本）、0 元免票券（权益流水留痕）分类入账，报表可追溯。
  - **运营人员配置**：新增「**会员专员**」岗位（招聘/日薪/满意度沿用员工体系），会员可归属专员（购卡接待、投诉积分补偿记录经办人），专员配置随员工管理页维护。
  - 模拟侧：会员会按卡等级折扣自助预约入园/设施（含自然消耗免票券与快速通行券）、在商铺用储值/券消费，散客也会被会员中心转化办卡，购卡收入持续滚动。
- **会员权益转赠与家庭账户（会员 × 受赠人 × 运营三方协作闭环）**：在「转赠·家庭账户」页面，会员把积分、储值或各类券类权益转赠给指定受赠人或家庭共享池，经运营审核、发放、领取、核销到撤回/退回全流程留痕，并与预约名额、商铺消费、积分储值和退款回补原子联动——
  - **家庭账户**：会员作为户主创建家庭并邀请注册成员（一名会员同一时刻仅能属于一个家庭，DB 部分唯一索引兜底）；户主/运营可邀请、移除成员，成员可主动退出，户主不可退出只能解散；解散时在途待审核/待领取的家庭共享转赠同事务自动回补各捐赠人。
  - **申请即托管（防超卖/防双花）**：转赠单一提交，积分/储值立即从捐赠人账户扣减托管（不产生现金流水，储值仍为负债），券类权益逐张由 `unused` 置 `locked` 锁定——锁定期间既不能二次转赠也不能用于预约/商铺核销。指定受赠人转赠进入运营待审核队列；家庭共享池可在运营配置中开启**免审**，提交即在同一事务自动通过进入共享池。
  - **审核与发放**：运营通过/驳回均幂等（`request_id`），驳回同事务把托管积分储值与锁定券全额返还捐赠人；通过后生成领取有效期（默认 7 游戏日，可配置），超期未领由日结扫描自动回补。全部多步写入包裹事务，任一联动失败整体回滚。
  - **领取与先领先得**：指定转赠仅受赠人本人可领取（也可婉拒回补）；家庭池任意在组成员可领取、先领先得，领取后转赠单记录实际领取人，池外成员无法领取。券类领取时捐赠人原券置 `gifted`、受赠人名下生成同面额/同到期日新权益（`origin_member_id` 溯源）；积分/储值直接入受赠人账户并写独立流水。
  - **核销与四大联动**：受赠人领取后即可用转入权益预约入园（免票券 0 元占名额、快速通行券走快速通道）、在商铺用储值/消费券消费（享会员折扣、赚积分、走联营分账与 FEFO 库存），与原生权益完全同口径；① **预约名额**：撤回在途已用票券时，同事务以园方原因**原子取消预约、全额退款、释放时段名额**（复用既有退款事务，积分回退/券返还联动先作用于受赠人）；② **商铺消费**：已在商铺核销的消费券/储值不可撤回（保护已成交消费，返回明确错误码）；③ **积分储值**：已领取撤回从受赠人余额冲回、不足则拒绝整笔撤回（不虚报）；④ **退款回补**：取消/驳回/拒绝/到期/解散各退回路径均按原口径返还积分储值、解锁券，逐条写捐赠人生命周期日志与财务可追溯口径。
  - **撤回与风控**：捐赠人可撤回待审核申请；待领取与已领取转赠可由捐赠人本人或运营撤回（未用返还、在途预约联动取消退款、已核销拦截），撤回原因、经办运营、取消预约数全部入时间线。
  - **配置与巡检**：运营可配置转赠模块开关、家庭池免审开关、领取有效期（1~60 游戏日）、单笔券类上限与最低转赠卡等级；每小时一致性巡检自动解锁「无在途转赠单引用」的锁定权益残留（自愈落 reconcile_findings），已领取单明细缺失仅告警不擅改资金。顶栏对待审核转赠与即将到期待领取实时红标提示。
- **园区联营商户结算**：在「联营商户」页面完成联营商户全生命周期——**商户申请入驻**（新商户登记意向，或存量商铺申请转联营）→ 运营**审核签约**（核定分成扣点 5%~80%、结算周期 3/7/15/30 天、保证金、会员优惠分摊比例；签约即收保证金并自动建铺/免固定租金）→ **按销售流水实时分账**（散客每小时成交、会员消费都在同一事务内拆出商户应得与园方扣点；会员卡折扣与消费券按合同在商户/园方间分摊）→ 五大联动：
  - **库存消耗**：联营销售同样走 FEFO 批次扣减（流水打标 `partner_sale`），消耗园区统采物资的**批次成本在账单中扣收**；销售退货回补库存并红冲成本；
  - **会员优惠**：会员折扣按合同 `member_discount_share` 拆分商户承担（账单扣减）与园方承担（营销成本），消费券营销成本园方承担；
  - **投诉处理**：联营商铺的客诉现金补偿结案时，按投诉严重度（一般×1/严重×1.5/紧急×2，带保底额）**罚没商户待结算款**归园方（同一投诉幂等不重复）；
  - **退货退款**：销售退货库存回补与现金退款原子提交，同步生成**负向红冲分账流水**，已出账单的退货在后续账单净额冲抵；周期净额为负（退货/罚没大于销售）自动结转下期、不出负账单；
  - **财务结算**：账期到期日结自动生成结算账单（应付 = 分账 − 会员优惠商户承担 − FEFO 批次成本 − 投诉罚没 − 保证金扣没 + 保证金退还），运营核对后支付清偿对商户负债；现金不足自动**挂账 overdue**，资金到位日结优先补付；终止合同出**清算账单**处理保证金退还/扣没。销售现金为园方代收（商业收入），账单支付时「商户结算」出账，与自营商铺（直接经营利润 + 固定租金）严格区分。
- **员工排班与动态调度**：在「排班工时」页面，运营主管与员工协作完成排班—考勤—结算闭环，并由**动态调度引擎**基于真实运营需求自动补位，与设施检修、投诉处置、预约客流和工资财务全链路联动——
  - **班次与排班**：内置早班（9~14）、中班（12~17）、晚班（14~18）与**跨日夜班（17~次日 9，含夜勤基准 6h）**四类班次模板；主管按员工 × 游戏日排班，同一员工同日只允许一个有效排班（DB 部分唯一索引 + 条件更新双重拦截**排班冲突**）。排班单带来源标记（手排 / 基础自动 / **动态补位** / 调班接替）。
  - **动态调度（基于需求画像）**：调度引擎每小时融合三类需求核算**班段（早/中/晚/夜）× 岗位（保安/保洁/维修）**缺口——
    ① **预约客流**：入园分时预约 + 热门设施预约按小时汇总，未来日按近 3 天散客均值外推预测，按「每名保安/保洁承载客流」阈值折算秩序与卫生岗需求（阈值可配置）；
    ② **检修工单**：每个在途检修工单需 1 名维修工，排队工单优先早班接单、检修中工单优先早/中班推进；
    ③ **投诉岗位需求**：待处置投诉按类别映射岗位（保安/保洁/维修），紧急投诉强制早班、其余按严重度摊入早/中/晚班。
    自动补位遵循**疲劳规避**（前一日上跨日夜班、次日凌晨才下班的员工不再排日班）、**区域/技能匹配**、**三日负载均衡**选人；当天已开始班段的硬需求（检修/紧急投诉）优先排未开始的**邻班接续**，仍补不上的缺口自动生成**紧急加班调令**（系统代发起、主管审批，批准后 1.5 倍时薪写入考勤并顺延下班）。报修、登记投诉、调班批准、取消排班、员工解雇离岗均会触发**联动重排**。可切换「动态调度 / 全员基础补位」两种模式，也可在页面一键手动执行。
  - **覆盖预警量化**：岗位覆盖页可按未来 3 天逐日查看，预警精确到班段 × 岗位的「需求 X 人 / 在岗 Y 人 / 缺口 Z 人」；未来班段缺口为黄色预警（引擎自动补齐），**当天班段已开始且为检修中工单或紧急投诉时升级为 ⛔ 红色硬缺岗**；同时保留「每个开放区域全日需有保安/保洁」的区域基线校验。派工侧硬门控不变——当日无排班不能接检修单、不能受理投诉。
  - **考勤状态机与跨日班次**：班次开始自动打卡（也支持手动补打卡，晚于班次开始记**迟到**），每游戏小时累计在岗工时；班次结束未打卡自动记**旷工**（无薪、满意度 -6）；员工可中途**离岗**（按实际出勤比例折算立即结算）；员工**解雇**时未来排班全部取消、待审批调班单作废、在岗考勤立即离岗结算，同时在修工单退回排队（离岗接续）。**跨日夜班**在看板上以「夜班待岗 → 当夜值守 → 次日凌晨值守 → 夜班已结」四阶段实时呈现，前一日夜班会在当日 9:00 下班、计入当日工资结算。
  - **调班与加班协作**：员工对未开始的排班发起**调班申请**（指定代班同事、目标班次与日期，可换日换班）或当值期间发起**加班申请**（1~4h，日班不晚于 18:00、跨日夜班不晚于次日 12:00），原排班进入「调班中」；**运营主管审批**——调班批准在同一事务内原子完成「原排班取消 + 代班人新排班」，提交后自动触发动态调度补齐调班留下的缺口；批准后下班点顺延，员工也可撤回待审批申请。
  - **工时结算与完工回写**：下班自动结算（**跨日夜班次日 9:00 结算、计入次日工资**），时薪 = 日薪 ÷ 5，按班次**基准工时**计薪、已批加班按 **1.5 倍时薪**另计（倍率可配置），旷工无薪、中途离岗按实际工时折算；每张考勤单生成一条「工资」财务流水（原全员固定日薪日结已被工时制取代），满意度变动（迟到/旷工/离岗扣分，**检修完工 +3、投诉补偿结案 +2**、加班补贴）在结算时统一落到员工士气。
  - 全链路写操作（排班/取消/打卡/离岗/调班/加班）均携带客户端 `request_id` 走**幂等表**重放，多步写入包裹事务，任一联动失败整体回滚；排班、考勤、调班、动态补位、紧急调令各动作逐条进入时间线可追溯。
- **跨日计划预览与审批（计划变更保持排班/工资/岗位覆盖一致）**：在「排班工时 → 跨日计划」页可开启**预览审批模式**（`scheduleApproval`），开启后引擎每小时与各类联动（预约下单/改签/退款/团确认/报修/投诉/调班）**不再直接改排班**，而是对未来 3 天做一次 **dry-run 推演**生成待批计划单——
  - **计划预览**：每条目列出「员工 × 日期 × 班段 × 班次/加班时长」，并快照其缺口依据（班段预约客流峰值、关联检修工单号与状态、投诉号与统一优先级分值）；同时给出**预估工资**（排班按基准工时时薪、紧急调令按 1.5 倍时薪×加班小时，与下班实际结算同口径）、每日需求画像（散客/会员/团队客流、在途工单、待处置投诉）与**模拟落地后的岗位覆盖残余缺口**。
  - **审批原子落地**：主管批准时在同一事务内对条目逐条**二次实时校验**（员工在岗、班次未过/允许补位、同日不冲突、跨日夜班疲劳规避、调令对象仍在岗且缺口仍存在），通过的排班/调令一次性写入（任一写入失败整体回滚，不留半成品）；已失效条目（员工被占用/离岗、班次已过）与**冗余调令**（缺口已被其他途径补齐）安全跳过并留痕，已落地条目回写真实排班号/调令号。落地后审批模式下残余缺口自动刷新为新的待批计划，始终保持排班、工资与岗位覆盖一致。
  - **需求指纹防过时**：计划生成时保存未来日「班段×岗位需求 + 工单/投诉状态」指纹；预约客流、检修工单或投诉优先级变化后（含库存变化事务 COMMIT 后联动），待批计划实时标记「🔄 需求已变化」，引擎自动计划则直接以新单取代旧单（旧单置 `obsolete`，同时仅保留一份 auto 待批单，同需求同 tick 去重），避免按过时画像误批。跨日推移后仍未审批的过期计划自动作废。
  - 审批同样携带 `request_id` 幂等；驳回不产生任何排班/调令、条目留痕；调令条目批准落地后生成 `source=dispatch` 的待审批加班申请，主管再批准即写入考勤、顺延下班，与既有调班/加班/工资闭环完全复用。关闭审批模式即回到「引擎直接自动补位」原玩法。
- **分期贷款**：可自选借款金额、期数（游戏日）与每期利率（等额本息）。每日闭园日结时自动扣 1 期并同步记录本金/利息流水；现金不足则按「利息→本金」部分偿还，余额挂账转逾期（按日计 2% 罚息、扣减声誉），后续日结优先补扣，也可随时提前结清（豁免未到期利息）。
- **领队组团（入园 + 多设施行程团队预约）**：在「领队组团」页面完成团队报团到核销结算的完整闭环，并与分时库存、客流、财务、设施停运和投诉全链路联动——
  - **提交与确认**：领队一次性提交入园时段 + 多个设施时段行程（5~120 人，设施须晚于入园），系统按牌价报价；运营确认时在**同一事务**内用条件更新统一锁定入园与各设施时段名额（任一时段余量不足整体回滚、不留占位），并按配置比例（默认 30%，可调）收取订金，即时记入「团订金」财务流水。每个行程生成一张 `source='group'` 的 **0 元预约单**（款项走团账统一结算，避免重复收费），与散客共用同一套库存且互斥可见，动态调度的预约客流画像天然把团队名额计入。
  - **分批核销与尾款结算**：到园后可对每个行程**分批核销**（闸机入园 / 设施口扫码，每批留痕、请求号幂等防重），尾款也可**分批收取**。核销有两道门控：① **先入园后游玩**——未完成入园核销不允许核销任何设施；② **款项门控**——已核销部分对应的应收不得超过领队已付净额，尾款未结清时只放行已付款人数，提示补交尾款。核销即时回写时段 `checked_count`，引擎将团队入园/游玩人数并入同一套**客流与设施游玩量**模型（走快速通道不排队）。
  - **部分退团与爽约**：行程开始前领队可按人数部分退团，按当前已付比例原路退回并释放名额；**游玩当日退团扣已付部分 50% 手续费**（记「违约」收入）。已核销部分不退、已开始时段不允许主动退。跨天仍未核销的团在引擎中自动**爽约结案**，未核销行程已付部分没收（违约收入）、名额转 `noshow`，团单置 `closed_noshow`。
  - **设施停运联动（重排或退款）**：设施检修/关闭/时段关闭/拆除时，停运批处理在散客退款的**同一事务**内分流团预约——优先把在途团行程**自动重排**到同日更晚的其他开放设施（原子转移库存、建立新团预约、园方原因不补差价）；入园时段无法安置则直接园方回退团款；设施一时无备选则**挂起（interrupted）释放名额**，领队/运营在页面选择重排任意开放时段/设施（不加价）或园方退款。每个受影响团自动生成一张**设施故障投诉工单**。
  - **回写与一致性**：名额锁定/释放、团预约状态、`reservation_slots` 核销与退款计数、团账（应收/订金/尾款/退款/没收）、财务流水（团订金/团尾款/团退款/违约）、客流与游玩量全部同步回写；所有写操作携带客户端 `request_id` 走幂等表，多步写入包裹事务，失败回滚并返回可追踪错误码，散客自动核销/爽约引擎显式跳过团预约由团模块统一处理。模拟侧：引擎会低频生成次日模拟团（自动确认收订金），游玩日自动补齐尾款并到点整团核销，驱动完整闭环。
- **统一客流预测与资源调度闭环**：在「客流调度闭环」页面，把预约、会员、团单与动态排班升级为一条「预测 → 调度 → 核销/退款 → 对账 → 学习」的统一闭环，避免排班、预约与财务状态不一致——
  - **统一客流预测（单一事实源）**：引擎每小时把未来三天的客流预测落库为 `flow_forecast_snapshots`，构成 = ① 散客/会员**入园分时预约**在途名额 + ② **团队名额**（已确认团全额计入、待确认团按 70% 置信折算，确认/拒绝后自动校正；团 0 元预约与散客共用同一套库存，天然不重复）+ ③ 热门**设施预约折算**（×0.35）+ ④ **散客外推**（近 3 天真实散客均值 × 自适应系数；今日散客由引擎实时产生、不重复外推）。动态排班的需求画像改为直接读取该统一预测，班段 × 岗位需求、跨日夜班（含闭园前 17:00 客流兜底）与前端看板完全同口径。
  - **库存变化即重排（提交后联动，回滚不联动）**：下单/改签/退款/超售补退、团队确认锁名额/退团/停运重排等库存变化在事务**成功 COMMIT 后**才登记联动（db 层 `afterCommit` 队列，回滚一律丢弃）——统一预测快照先刷新，动态调度引擎再按新缺口补位；联动失败只记日志，不影响已提交的业务事务。杜绝"事务已回滚、排班却按幽灵库存重排"的不一致。
  - **检修 / 投诉统一优先级**：维修资源与紧急调令不再只看类别，而按统一分值排序——投诉 = 严重度基础分（30/55/85）+ SLA 剩余时限紧迫度（临期/超时加权）+ 升级加权；检修 = 检修中(70)/排队(50) + 低进度加权。需求画像内投诉/工单按分值挂载，跨班段补位、邻班接续与紧急加班调令全部按分值先后占人，维修缺口优先匹配工单所在区域。
  - **跨日班次衔接**：跨日夜班（17:00~次日 9:00）纳入统一需求——夜班保安需求取「每 N 区域配比」与「17:00 闭园前预测客流折算」的较大值；疲劳规避（前夜夜班次日不再排日班）之外，巡检额外兜底识别「前夜夜班 + 次日 9:00 前早班」的硬冲突并报 block。
  - **闭环一致性巡检（对账 + 安全自愈）**：引擎每小时（页面也可手动触发）对账五类口径：① **时段库存计数器**——以预约单为事实源重算 booked/checked/noshow/refund，漂移即**自动校正**（仅改计数列、不动资金）；② **退款资金**——每笔现金退款须有等额财务流水，缺失报 block（不擅改现金）；③ **团账**——订金/尾款/退款/手续费流水合计须等于团单字段；④ **考勤结算**——已下班/离岗/旷工考勤须有结算日（防漏结工资）；⑤ **跨日排班冲突**。告警落 `reconcile_findings` 并在严重项出现时登记经营事件、顶栏红标提示，人工核对后可忽略。
  - **日结自适应学习**：每日闭园用当日实际入园（减去预约核销入园得真实散客）对比前一日预测快照，EMA 平滑更新散客外推系数（0.6~1.6 限幅），并回填预测命中率；无散客基线的首日不学习以免污染。越运营预测越准、排班越贴合真实客流。
- **园区应急指挥（安全事件全状态流转与多角色协作）**：在「应急指挥」页面围绕火情、设备事故、拥挤踩踏、食物中毒、极端天气、治安等安全事件，运营、安保、游客三角色协同完成 **发现 → 分级 → 封控 → 疏散 → 控场 → 复园 → 复盘** 全流程，并与设施停运、预约退款、投诉、岗位调度和财务补偿全链路联动——
  - **发现与分级**：安保巡报、运营发现、游客一键紧急求助均可上报；游客上报自动生成安全投诉。运营核定 **1 一般 / 2 较大 / 3 重大 / 4 特别重大** 四级并设置封控时限（6/4/2/1 游戏小时）。上报后 4h 未分级系统按建议级别自动核定；超封控时限未控场自动升级（直至 4 级）并扣减声誉。
  - **分级即封控（联动设施停运与预约退款）**：2 级以上默认封锁事发区域并应急停运区内设施（可手动增删封控对象），复用分时预约停运联动——关停时段、在途散客预约**园方全额退款**、团队行程自动重排或退款、自动生成安全投诉，全部在同一事务提交（任一步失败整体回滚，不留"封了但款没退"的半完成状态）。**4 级特别重大事件全园封控**：关停全部入园时段并退款在途入园预约，封控期间新生成的未来入园时段也保持关闭。
  - **疏散与控场**：封控后安保现场组织游客疏散（可分批上报增量、累计疏散人数），险情控制后核定受伤人数并确认控场。
  - **复园恢复与财务结算**：确认现场安全后一键复园，系统按封控前状态恢复设施/区域、重开预约与入园时段（封控期间新增的检修工单则尊重检修流程，不强行复运）；按等级结算**应急抢险费用**（¥800/2500/6000/15000，可覆盖）与**应急岗位补贴**（封控 120 / 疏散 150 / 抢险 200 / 医疗 180 元每人次），逐条记入财务流水，到场安保满意度 +3。
  - **事故复盘**：复园后登记事故原因认定、整改措施、经验教训与 1–5 星处置评分；按时控场、评分高可回补声誉（受伤与高等级扣减），关联安全投诉随复盘自动闭环。经核实为误报可随时关闭并解除全部封控，不计抢险费用。
  - **岗位调度（安保协作）**：运营向事件调派员工编组（封控警戒/疏散引导/抢险救援/医疗救护），安保在现场**到场确认 / 撤防**；排班在岗校验与动态调度打通——分级产生安保岗位需求，自动补位或生成紧急加班调令（审批模式下进跨日待批计划）。
  - **游客理赔与财务补偿**：游客可就受伤、财物、门票损失登记理赔并自动生成安全投诉；运营核定后现金赔付（计入「应急补偿」财务流水）或驳回（需说明），赔付/驳回同步闭环关联投诉；现金不足或重复赔付被原子拦截。安全投诉在「投诉补救」页可一键**转报应急**升级为安全事件。
  - **经营影响与一致性**：在途事件按最高等级折减散客客流（1 级 ×0.92 … 4 级 ×0.15）并压低现场满意度，重大以上事件每小时持续侵蚀声誉；全部写操作携带客户端 `request_id` 走幂等表重放，多步联动包裹事务，顶栏对在途事件与待核定理赔实时红标提示。
- **园区物资采购与库存（运营 × 商铺协同供应链）**：在「物资采购库存」页面与供应商协同完成 **供应商 → 采购单 → 入库批次 → 库存 → 销售/退货 → 结算 → 对账** 全闭环，库存实时联动商铺销售、缺货预警与财务结算——
  - **供应商与物资档案**：维护供应商（品类/联系人/账期 0~N 天/评级/暂停合作）与物资目录（标准成本/安全库存/保质期/自动补货建议量/首选供应商）；每个商铺可配置一组供货物资（未配置的商铺保持原有"无库存约束"销售，向后兼容），商铺卡片实时显示库存充足/偏低/断货徽标。
  - **采购单协同流转**：采购单草稿可由**运营提报、商铺协同提报（带来源商铺）、缺货自动生成**（按首选供应商分组、低于安全库存且无在途单时幂等生成，不重复下单）三种来源产生；经 **提交 → 运营审批 → 供应商备货 → 分批收货** 流转，支持部分到货、超收拦截、驳回作废、完整流转日志。
  - **批次入库与 FEFO 销售联动**：每次收货生成独立入库批次，携带批次单价（最近批次价自动回写标准成本，价差超 30% 挂价格异常）与到期日（按物资保质期推算）。散客每小时销售与会员现金/储值/券消费均**实时按 FEFO 先到期先出扣减批次**——已过期批次不参与销售；商铺任一挂供物资断货即按最小可售量限销，未成交需求逐时段记入缺货流失（流失营收可对账），会员整单购买在支付同事务内校验库存，缺货整单回滚不扣款。
  - **财务结算（现金制，全程原子事务）**：账期 0 天供应商收货即自动付款（现金不足不阻断收货，未付部分转挂账并生成应付异常）；账期供应商按「批准日+账期」算应付日，可分批付款、超额付款被拦截，逾期每天巡检升级；采购付款、过期报损、盘亏核销统一记入「物料成本」财务流水。
  - **双向退货**：采购退货退供应商——优先退出该单批次并回减库存，未付货款冲减应付、已付款部分供应商现金退回；游客销售退货——按商铺售价退还现金（商业流水红字），物资按原批次回补。
  - **盘点调账**：支持全仓/按商铺盘点，录入实盘后自动比对账面，差异生成账实不符异常；审批后盘盈按标准成本入库、盘亏按 FEFO 核减批次并确认物料成本损失。
  - **临期过期与异常对账**：2 天内到期批次自动临期预警（提示优先促销/退供），到期批次整批报损核销成本；异常对账中心汇集缺货断货、临期过期、价格差异、账实不符、逾期货款五类异常（警告/紧急分级、同类去重、严重度自动升级），可逐条核销或忽略形成闭环。引擎每小时自动推进：生成补货草稿 → 批准满 3 小时自动到货 → 过期报损 → 异常巡检。
- **供应商批次召回（供应商 × 园方 × 联营商户 三方协同闭环）**：在「批次召回」页面针对某个供应商的问题物资批次发起召回，系统串联库存隔离、商铺下架、游客退货退款、批次退供/销毁、供应商赔付与投诉/事件联动——
  - **发起即隔离停售**：可选择问题物资的**全部在库批次**或**指定批次**，发起瞬间把批次可用量转入 `quarantined_qty` 隔离量（在库实物总量不变，但立刻从 FEFO 销售与盘亏/退货/报损路径中排除，任何销售不得消耗隔离量），批次锁定召回单防止重复隔离。
  - **三方任务自动分派**：按物资↔商铺供货映射，把净售出过该物资的**自营与联营商铺**逐家登记为受影响方（按库存流水汇总净售出量）并写入时间线；同时自动生成**餐饮质量投诉**（严重度随召回等级，主责商铺取销量最大者）与一条**召回事件通知**（顶栏红标提醒）。
  - **供应商受理 → 商户协同**：供应商受理后召回进入处置中；联营商户在详情中**确认知悉下架**（自营由园方统一处置，无需确认）。
  - **游客退货退款（销售联动）**：逐铺按已售出净量为游客办理退货退款，数量受净售出上限约束；**自营**商铺园方直接退现金（负「商业」流水），**联营**商铺园方代付后写一条**负向联营红冲行**结转下期结算（问题品按召回处置**不回补库存**，仅记 `recall_refund` 流水冲减净售出，杜绝问题货二次上架）。
  - **隔离批次退货 / 销毁**：退回供应商——先冲该采购单未付应付、已付款部分现金退回，写采购退货单与库存出库流水；现场销毁——按批次成本核销「物料成本」损失。两路径都同步核减隔离量、批次量与库存。
  - **供应商赔付与结案**：赔付报价 = 批次货款损失 + 游客退款 + 按严重度（一般 0%/严重 20%/紧急 50%）的**罚则**，供应商现金赔付到账记「召回赔付」收入；仍有隔离批次时拦截结案，全部处置完后一键闭环——关联餐饮投诉随赔付**自动结案**、事件置为已处理、严重/涉健康问题供应商评级自动下调。**误报/撤销**则解除全部隔离恢复销售、投诉中性关闭。全部多步写（批次/库存/现金/流水/分账/投诉/事件）在同一事务原子提交。
